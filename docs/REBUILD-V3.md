# Rebuild v3 after the server CPU/RAM upgrade — one-shot checklist

Context: v3 (gzip ramdisk) was already built successfully on the server before it
was shut down for the upgrade:

```
~/twrp-mars/dist/boot.img   201326592 B
sha256 d4eb1c6f092f762d0832b6159be119527ba8514292b35afd7de20d528c135584
RAMDISK_FMT [gzip]   KERNEL sha256 2287c094…f7e8bf (LOS stock)   jobs 12
```

So this checklist is about (a) putting the tooling defaults right, (b) optionally
rebuilding to confirm, (c) getting the image onto the phone. Nothing here flashes
a device. The old `~/fox_14.1/out` and `.ccache` are warm, so a rebuild is
~10 minutes (Soong re-analysis + recompress), not hours.

## 0. What the shutdown left behind

* `systemctl stop mars-build` + `disable mars-build` — the unit will not start
  itself after the reboot.
* Anything killed by `pkill` can have left stale locks. Check before building:

  ```sh
  find ~/fox_14.1/.repo -name 'index.lock' -o -name 'shallow.lock' 2>/dev/null
  ls -l ~/fox_14.1/out/*.lock ~/fox_14.1/out/.lock 2>/dev/null
  pgrep -af 'build-local.sh|soong_ui|ninja|ckati'   # wants: no output
  ```

  A lock is only stale if no build process owns it (`fuser`/`lsof` can confirm);
  then `rm -f` it. The repo locks are recreated on the next `repo sync`, and
  `~/fox_14.1/out` is regenerated by kati — nothing is lost by removing a stale
  one, but a live one must never be deleted.

## 1. Tooling defaults that changed (commit `1b3173b` + the follow-up)

| what | before | now |
| --- | --- | --- |
| ramdisk compression | `OF_USE_LZMA_COMPRESSION := 1` → LZMA-alone, kernel cannot unpack it | `BOARD_RAMDISK_USE_LZMA := false` → gzip (kernel has `CONFIG_RD_GZIP=y`, no LZMA) |
| `scripts/check-tree.sh` | — | fails in ~10 s if any non-gzip ramdisk compression is re-enabled (negative-tested) |
| `build-local.sh` `--jobs` | nproc | nproc **capped at 12**; `MARS_JOBS=N` / `--jobs N` override |
| kernel step | always downloaded, silently replacing `prebuilt/Image` with the default BakaSU release | **auto**: keep an existing `prebuilt/Image`, download only if missing; `--force-kernel` / `--kernel-url` to replace; section 5 prints the sha256 + `Linux version` of the Image actually used |
| `BUILD-INFO.txt` | `kernel: <URL>` (misleading — it printed the URL even when nothing was downloaded) | `kernel sha256` + `kernel version` of the real `prebuilt/Image`, plus `jobs` |
| `mars-build-run.sh` | `MARS_JOBS` default 4, "4 cores / 15 GB this box" | default nproc capped 12, mem thresholds 2000/4000 MB |
| CI workflow kernel step | `fetch-kernel.sh <url>` | `KERNEL_FORCE=1 fetch-kernel.sh <url>` (an explicit CI input must still win) |

## 2. Get the tooling onto the server without clobbering its local fixes

`~/twrp-mars/scripts/build-local.sh` carries **uncommitted** server-only fixes
(`mka bootimage` instead of `mka recoveryimage` for `BOARD_USES_RECOVERY_AS_BOOT`,
the `OVERRIDE_ENABLE_UFFD_GC=false` override, and the robust collect step). They
must be preserved, and they should be committed so that the repo and the server
stop diverging.

Recommended order (the agent does this once the box is back):

```sh
# 1. capture the server-local file
ssh shen@server 'cat ~/twrp-mars/scripts/build-local.sh' > /tmp/build-local.server.sh
# 2. commit it verbatim (server-only hunks on top of the repo version)
# 3. re-apply the --jobs/--kernel defaults on top of that commit
# 4. push, then on the server:
cd ~/twrp-mars
git fetch origin
git checkout -- scripts/build-local.sh          # safe: content is now in the repo
git pull --ff-only
bash scripts/check-tree.sh                      # expects: ALL CHECKS PASSED
git status --short                              # expects: only device.mk + firmware/ + recovery/root/vendor/ (v2 blobs)
```

If the server file is *not* committed, update the other paths only, so that the
local modifications survive:

```sh
cd ~/twrp-mars
git fetch origin
git checkout origin/main -- \
    fox_mars.mk scripts/check-tree.sh scripts/fetch-kernel.sh \
    scripts/mars-build-run.sh docs/BUILD-STATUS.md .github/workflows/build-recovery.yml
```

## 3. Rebuild

```sh
cd ~/twrp-mars
mkdir -p logs
nohup ./scripts/build-local.sh --fox-dir "$HOME/fox_14.1" --skip-sync \
      > logs/v3-rebuild.log 2>&1 &
tail -f logs/v3-rebuild.log
```

* no `--skip-kernel` is needed: the default now keeps `prebuilt/Image`;
* check section 5 of the log — it must print
  `2287c094ea0291fc21f231273af3cd3d3af80efffb1f2a5f5b06aa9e04f7e8bf` and
  `Linux version 5.4.302-qgki-g7ede20c8692e …`. If it prints
  `g797c093f5b52`, the BakaSU kernel has come back (see §1) — stop and fix
  before testing on the phone;
* `jobs: 12` should be in the header (17 GB of swap is not a substitute for RAM,
  but 12 concurrent jobs have been fine on this box).

## 4. Verify the artifact

```sh
cd ~/twrp-mars
ls -l dist/boot.img && sha256sum dist/boot.img
MB=~/fox_14.1/external/magisk-prebuilt/prebuilt/magiskboot_x86_64
( cd /tmp && rm -rf mb && mkdir mb && cd mb && \
  cp ~/twrp-mars/dist/boot.img . && "$MB" unpack boot.img | \
  grep -E 'HEADER_VER|KERNEL_SZ|RAMDISK_SZ|RAMDISK_FMT|CMDLINE|PAGESIZE' )
# expects: RAMDISK_FMT [gzip], HEADER_VER [3], KERNEL_SZ [39428608], PAGESIZE [4096], CMDLINE [twrpfastboot=1]
```

Then bring it to the container (resume, do not re-download the first 124 MiB):

```sh
# on the container: keep the 124554240-byte prefix, fetch only the remainder
dd if=~/twrp-mars/dist/boot.img bs=1 skip=124554240 \
  | ssh shen@server 'cat > /tmp/boot-v3.tail'      # or rsync --append-verify
cat /tmp/boot-v3.tail >> /root/mi11/work/twrp-dist/boot-v3.img
sha256sum /root/mi11/work/twrp-dist/boot-v3.img   # must equal the server's
```

Do **not** zero-pad a truncated copy: the AVB/vbmeta payload sits after the
ramdisk, so a padded file is not the image (verified: sha256 differs).

## 5. Put it on the phone

```sh
# container -> Download/DSHA (the bridge's export path)
curl -s -H @/root/.dsh/.bridge_headers \
  "http://127.0.0.1:3090/app/export?path=/root/mi11/work/twrp-dist/boot-v3.img"
# then into Download itself, via the protected device shell
/root/dsh-bin/adb-shell "cp /sdcard/Download/DSHA/boot-v3.img /sdcard/Download/boot-v3.img"
/root/dsh-bin/adb-shell "ls -l /sdcard/Download/boot-v3.img"
```

## 6. Test on the device (nothing is flashed)

```sh
termux-fastboot boot boot-v3.img
```

Expected: OrangeFox comes up. If it still does not, adb now runs before the GUI,
so it is diagnosable:

```sh
adb shell 'grep -E "Modules Loaded|msm_drm" /tmp/recovery.log'
adb shell lsmod | grep -E 'msm_drm|fts_touch_spi|xiaomi_touch'
```
